## Context

两件事：
1. **认证完全独立**：废弃 ERP/admin 依赖（finance_session、跨库 hr_employees 查询），本项目自建用户表 + 邮箱密码登录 + 本地会话。用户管理按约定不做 UI——提供一个 CLI 脚本做增删改（底层仍是 DB）。
2. **按 DragonCode 文档对齐生图参数**：UI 目前提交像素尺寸（`1024x1536`），文档要求 `size` 为比例字符串（`1:1`/`auto`）；且代码的 4K 白名单（15 种比例）与文档（仅 16:9/9:16/2:1/1:2/21:9/9:21）不符，现状态会触发 API 报错。

存量数据无缝衔接：迁移时为现有 user_id 在本地用户表建档（无密码、占位邮箱），任务/图片归属不受影响。

## Part 1 — 独立用户体系

### 数据层（src/lib/db/schema.ts，SCHEMA_VERSION 递增）
- 新表 `playground_users`：`id CHAR(36) PK`、`email UNIQUE`、`display_name`、`status`（active/disabled）、`password_hash`（可空=NULL 不能登录）、`created_at`、`last_login_at`
- 新表 `playground_auth_sessions`：`session_token CHAR(64) PK`、`user_id`（FK→playground_users CASCADE）、`expires_at`、`created_at`、`user_agent`
- 迁移：动态查 `information_schema` 找到 5 个指向 `hr_employees` 的外键 → DROP → 改指向 `playground_users(id) CASCADE`；回填存量用户（`SELECT DISTINCT user_id` from tasks/image_owners/groups → 占位邮箱 `<id>@users.local`、status='active'、password_hash=NULL）

### 认证重写（src/lib/db/auth.ts，93 行，全库唯一读 admin 处）
- 会话 cookie：`image_studio_session`（httpOnly），本地 `playground_auth_sessions` 校验（30 天，登录时顺带清理过期行）
- `getCurrentUser()`：只查本地会话 + 用户表 status='active'；**删除 finance_session/admin_cosmorigin 全部逻辑**
- 密码：Node 内置 `crypto.scrypt` + `timingSafeEqual`（salt:hash 存储，零新依赖）
- `requireCurrentUser` 签名/错误语义不变 → 14 个 API 调用点零改动；worker 不动

### API 与页面
- `POST /api/auth/signin`：{email, password} → 校验 → 签发会话 + 更新 last_login_at（失败统一文案防枚举）
- `POST /api/auth/logout`、`POST /api/auth/password`（登录后改自己密码）
- 新增 `src/app/signin/page.tsx`：极简邮箱+密码登录页（Tailwind 风格与现有一致）
- `src/components/auth/AuthGuard.tsx`：401 → 跳本项目 `/signin?redirect=...`（删除 ERP 跳转）
- `src/proxy.ts`：移除 finance_session query→cookie 桥接（ERP 遗留逻辑）
- `NEXT_PUBLIC_DASHBOARD_URL` 相关引用清理

### 用户管理（无 UI）
- 新增 `scripts/manage-user.mjs`：`add / set-password / list / disable / enable`（读 .env 连 DB，scrypt 加密），在服务器上通过 CLI 维护用户

## Part 2 — 按 DragonCode 文档对齐

- **size 提交格式**：提交时把像素尺寸转成文档支持的比例字符串（新增转换函数：像素 → 精确比例 → 不在支持列表时吸附到最近支持比例；`auto` 原样）。应用在两处：web 端 `normalizeParamsForSettings`（paramCompatibility.ts，为 DragonCode profile 计算 `sizeRatio` 附带参数，provider 定义改用 `$params.sizeRatio`）+ worker 端 `createSubmitPayload`（worker/src/providers/gpt-image-2-async.ts，无 sizeRatio 时自行从 params.size 转换，兼容存量任务）
- **4K 白名单修正**（src/lib/size.ts `isSupported4KRatio`）：改为文档的 6 种比例（16:9/9:16/2:1/1:2/21:9/9:21）——UI 的 4K 选项展示与自动降级逻辑同步修正
- 其余已吻合：提交/轮询路径、`data.result.images.*.url.*`、n=1、image_urls≤16、错误路径、计费字段
